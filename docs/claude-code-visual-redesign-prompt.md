## 2. 确定的整体设计

风格名称：**深色磨砂工作台**。

保留完整壁纸画面、人物轮廓和轻量个性装饰；用统一的冷炭灰玻璃组织导航、工作区和输入区域。视觉优先级是：正文与输入操作 > 导航与工具 > 壁纸和挂件。

工作区应呈现为一块连续的磨砂表面，内部是标题、消息、工具结果与底部输入框。取消 transcript 额外形成的整块深色背板。输入框通过较高不透明度与细边线体现操作层级，而不是与正文上下拼出两个大黑块。

### 2.1 视觉参数

以下数值是首轮实现的基线，应结合实际截图微调。所有 alpha 均指所在表面的背景不透明度，不能把多层叠加后的观感当成单层数值。

| 项目 | 基线 |
| --- | --- |
| 玻璃底色 | 冷炭灰，约 RGB(22, 25, 31)；各表面保持同一色系 |
| 侧栏 | alpha 0.78，blur 16px |
| 主工作区 | alpha 0.64，blur 16px |
| DOM 内可控制的顶栏 | 同色系，整体观感接近 alpha 0.72；与父表面叠加时相应降低自身 alpha |
| transcript 内容列 | 新风格下无额外整块背景、模糊和卡片阴影 |
| 输入框 | alpha 0.86；不再叠第二次大面积 backdrop blur |
| 玻璃饱和增强 | 约 1.05–1.10，避免当前 1.35 左右的增强使背景再次变艳 |
| 主表面 / 输入框 / 浮层 / 小控件圆角 | 18 / 14 / 16 / 8px |
| 表面边线 | 1px，白色 alpha 0.06–0.08；只在需要分界的表面使用 |
| 阴影 | 轻量、低对比；主表面最多约 `0 12px 32px rgba(0,0,0,.14)`，避免每层都有阴影 |
| 壁纸参数 | opacity 0.50，brightness 0.80，contrast 1.02，saturate 0.85，blur 0，dim 0.10 |
| 壁纸切换 | fade，约 900ms |
| 普通交互反馈 | 约 140–180ms；明显可见的键盘焦点 |
| 主要文字 / 辅助文字 | 参考 #ECEFF3 / #ADB4BF，以宿主现有主题令牌为优先来源 |
| 扩展控制面板强调色 | 克制的灰蓝，参考 #8EA7C4 |

只对扩展新增或明确需要优化的界面使用自己的文字、间距和控件令牌。保留宿主字体、图标体系、正文排版和代码等宽字体；不全局覆盖应用字号。保留警告、错误、diff 增删等语义色。

### 2.2 布局与层次

1. 优先在现有 `main` 工作区边界内统一材质，不新建宿主替代页面、不移动 React 节点、不重做滚动容器。
2. 新风格下让 transcript 容器透明，清掉的是本项目注入的整块背景；消息气泡、代码块、附件、diff、工具结果卡片保留必要背景。
3. 输入框与正文使用一致的对齐关系和现有内容宽度，底部留出约 12–16px 的舒适间距，避免贴边或压住最后一条消息。
4. 保留原有侧栏宽度、收起/展开逻辑与右侧预览/终端/代码面板布局。不要全局改变 flex、overflow、position 或强制 transcript 固定宽高。
5. 左侧选中项使用轻微填充与边界，hover 更轻；不添加新的彩色标记，不因 hover 改变尺寸。
6. 顶栏只优化确认可控的页面 DOM。无法由注入控制的 Windows 原生标题栏、系统菜单和窗口按钮保留原样，并在报告中说明范围。
7. 不隐藏截图中的附件占位、原生操作按钮或用户内容来制造更干净的截图。

### 2.3 个性装饰与动效

- 保留用户原有挂件图、头像、自定义文件路径。
- 挂件可以缩小约 15%–20%，置于主工作区顶部靠右的安全空位，避免标题、窗口按钮、侧面板按钮和正文；位置需按实际 DOM 边界计算、限制在视口内，不能只硬编码一个百分比。
- 保留挂件的点击开面板、下拉、左右拖动和持久化能力。
- 新风格默认关闭点击粒子、鼠标拖尾，界面视差为 0，壁纸视差默认关闭；这些功能继续可由用户重新开启。
- 支持 `prefers-reduced-motion`，减少非必要位移与长过场，不强迫关闭用户主动播放的内容。
- 不增加持续发光、鼠标追光、额外粒子、噪点动画或新的装饰组件。

### 2.4 壁纸亮度适应

在新风格下提供可关闭的“自动增强可读性”，仅微调玻璃遮罩强度。

- 尽量复用已有壁纸取样与 live frame 能力，在壁纸准备就绪后读取约 32×32 的代表画面。若现有函数只返回主色，不把主色误称为平均亮度；必要时从小图计算亮度统计。
- 亮图适当增强遮罩，暗图适当减弱。深色主题建议限制在：main alpha 0.58–0.74、sidebar 0.74–0.84、composer 0.84–0.92。
- 每次壁纸切换只做少量取样；视频可以在可播放后的非黑首帧取样。不要每帧读像素，也不要因视频闪动频繁改变界面。
- 异步取样结果必须核对当前壁纸标识/切换序号，旧壁纸的迟到回调不能覆盖新壁纸。
- 跨域、未就绪或 live 取样失败时使用基线值，仍能正常阅读和播放。
- 不取聊天内容的截图做分析，不上传任何截图或壁纸。
- 新风格的推荐配置关闭现有 `fx.autoTint`，让当前宿主明暗主题稳定；“自动增强可读性”不能自行改写 `data-theme`。保留原“主题随壁纸”功能供用户主动开启，两者语义要清楚，手动主题选择优先。
- 用户切到浅色主题时，应有同样层次的浅色玻璃和深色文字。浅色玻璃遇到暗壁纸时可能需要提高遮罩强度，应按深色文字的可读性判断，不能机械套用深色主题的调整方向。停止注入时恢复宿主状态。
- 全局取样只能改善可读性，不得声称保证任意壁纸、任意位置都满足特定对比度标准。

## 3. 配置和控制入口

实现一个明确可切换的外观模式：`原有外观` / `深色磨砂工作台`。不扩展出多个全新主题或主题商城。

1. 检查 `src/config.mjs`、`src/commands.mjs` 和现有预设机制，优先复用已有键。只增加外观模式、独立侧栏强度、自动增强可读性等真正缺少的设置。具体 schema 自行选择，同一模式下的一个参数只能有一个权威来源。
2. 侧栏强度必须与 transcript 的 `contentAlpha/contentBlur` 解耦，不能继续通过内容卡片参数间接控制侧栏。
3. 没有新字段的旧配置仍能读取，读取不能偷偷重置或反复改写用户配置。新模式通过显式操作启用。
4. 新模式应保持可调。效果面板清楚区分“壁纸画面”“界面玻璃”“动效”，当前模式不生效的旧卡片控件应隐藏或说明，不能留下看似可调但无效果的滑杆。
5. 新增控制要接入现有共享命令入口；面板与 CLI 行为一致，CLI 帮助同步更新。不要仅支持手工编辑 JSON。
6. 提供“恢复优化前外观”的实际可用入口：恢复本次涉及的视觉字段，不回退播放列表、当前壁纸、播放进度或其他非视觉状态。不直接套用会覆盖全部配置的整机预设充当视觉恢复。
7. 在当前机器显式启用新风格前，先给 `~/.chatgpt-wallpaper/config.json` 做带时间戳的完整备份，再记录本次要改的视觉字段，支持后续只恢复视觉外观。
8. 本轮允许调整的当前运行配置仅包括视觉参数、主题跟随开关、相关动效开关及挂件大小/位置。播放列表、轮换顺序与间隔、当前壁纸、音量、倍速、live 开关与帧率、自定义资源路径、自启动和看门狗设置均保留。

## 4. 实施位置与边界

开始前核实这些文件，不假设函数名或选择器永远不变：

- `src/inject.js`：`panelCss()`、`applyFx()`、壁纸取样、主题处理、事件和定时器生命周期。主要完成表面统一、作用域、可读性适应与清理。
- `src/panel.js`：扩展面板 CSS、`renderFx()`、挂件定位与交互。对齐视觉令牌，增加必要控制和恢复入口，保留现有六个页签的功能。
- `src/config.mjs`：兼容默认值、读取合并和持久化。
- `src/commands.mjs`：新增字段验证、共享命令、只涉及视觉字段的应用与恢复逻辑。
- `src/bridge.mjs`：只在新增配置需要状态透传、CLI 映射或命令支持时修改；留意常驻推送与 `pokePages()` 两条路径不能漏传。
- `src/usage.txt`、`README.md`：更新新增入口和恢复方法，保持简洁。
- `tools/inspect-layout.mjs`、`tools/verify-injection.mjs`、`tools/cdp-screenshot.mjs`：优先复用现有诊断工具，必要时小幅补充。

工程约束：

- CSS 只作用于壁纸启用和目标外观模式下确认匹配的表面。使用明确、带前缀的属性/类和 CSS 变量，不写宽泛的 `div`、全部 `main *` 或全部按钮覆盖。
- 当前可参考 `main[class*="MainContentSurface"]`、`main [class*="transcriptContent"]`、`main [class*="ComposerLayoutRoot"]`、`aside.app-shell-left-panel`。必须现场验证，避免依赖构建哈希。
- 某个表面未匹配时保留原生界面。必要锚点不存在时避免先透明化所有根容器，造成整页无遮罩。
- 保留现有注入 build hash、复用保护、自动重挂载、媒体代理和生命周期。新增的属性、样式、监听器、observer、timer 与 rAF 必须能正确清理。
- 默认尽量只让侧栏和主工作区承担大面积 backdrop blur；不要在主面板、transcript、消息、输入框上层层叠磨砂。不使用 `will-change` 覆盖整棵 DOM。
- 不重写应用，不改 WindowsApps 安装文件，不改 vendor 渲染器，不引入新的框架、字体下载、图标库或 npm 依赖。
- 不删除、覆盖或提交用户无关改动，不将个人配置、截图、壁纸或绝对资源路径提交到仓库。最终不自动提交、推送或创建 PR。

## 5. 按顺序执行

### 第一步：基线与备份

读取配置并记录 git diff、桥接 PID、看门狗状态、当前壁纸、播放列表和关键用户设置；检查实时 DOM，保存同一窗口的优化前截图。完整配置备份不得放到公开文档中。

### 第二步：统一表面

先实现外观模式与令牌，再完成侧栏、工作区、可控顶栏、输入框的统一。移除新模式下 transcript 的独立大背板，保留语义卡片背景。先用固定基线验证可读性和布局。

### 第三步：控制与兼容

完成侧栏独立调节、模式切换、视觉恢复、共享命令/CLI、面板说明和旧配置兼容。对新增的非纯样式逻辑做有意义的验证。

### 第四步：适应与装饰

接入低频壁纸亮度适应，处理异步迟到和失败回退；收敛挂件位置、动效与扩展面板材质。不扩展无关功能。

### 第五步：在真实应用启用并验证

修改源码后，完成备份并显式启用新风格。桥接启动时会缓存注入源码，不能只改文件就声称生效。通过实际重启/重新注入使新 build 挂载，并核实。

重启只针对壁纸桥接，不退出 Codex、不关闭用户对话。考虑看门狗会重新拉起桥接，必要时临时停止并在结束时恢复此前的启用状态；不修改其自启动注册。Windows 后台启动使用 `Start-Process -WindowStyle Hidden`、明确的工作目录和独立日志，确保只有一个桥接实例。

对于新增的配置兼容、视觉快照恢复、数值校验、亮度映射与过期结果处理，按实际实现使用 Node 内置测试或独立验证脚本，覆盖旧配置、边界值、取样失败与仅恢复视觉字段等真实行为。无需为纯 CSS 常量编写镜像测试，也不安装测试框架来凑测试数量。

真实界面至少确认：

- 同一壁纸、窗口尺寸、滚动位置下的前后截图，验证改动确实来自界面设计。壁纸若测试中切换，结束后恢复原来的选中项、轮换状态和关键配置。
- 明亮高饱和壁纸、暗壁纸、图片与可用的视频/Scene 场景；不能用全黑壁纸掩盖问题。只验证本机可用的类型，缺失项如实记录。
- 当前窗口尺寸、一个较窄窗口、打开右侧预览/终端面板的场景；测试后恢复临时改变的窗口/主题状态。
- 正文、代码块、附件、工具结果、输入框、补全菜单、弹窗可用；输入法组合输入与键盘焦点正常；不得发送测试消息给外部人员或其他对话。
- 侧栏仍能展开/收起，选中项清楚，滚动与流式输出正常，挂件不挡操作，扩展控制有效。
- 手动明暗切换、自动可读性开关、原有外观切换、视觉恢复、新模式重新启用均有效。
- 停止桥接时，本轮注入的额外属性和样式被清除；再次启动后配置生效，不出现重复壁纸层、重复控制面板或不断累积的监听器。
- 比较同场景下滚动与空闲表现，检查是否增加了不必要的持续 rAF、取样或重复样式写入。报告实测事实；没有采集性能数据时，不声称 CPU/GPU 降低了某个百分比。

验收标准：

1. 整体材质和色调一致，正文与输入区属于同一工作区，不再是上下拼接的大黑板。
2. 壁纸保持可辨认的细节与色彩，文字区域稳定清楚，侧栏不会再次完全透明。
3. 配置可调、切换可逆、旧配置可用，用户原有资源和播放行为保留。
4. 没有遮挡、点击穿透错误、滚动破坏、快捷键回归或重复注入。
5. 有真实运行截图和状态证据；若本机无法连接 CDP，保留代码并明确标注哪些视觉项尚未验证，不能宣称已达到视觉验收。
